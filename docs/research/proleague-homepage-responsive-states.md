# Pro League — адаптивність і стани головної

Дата: 2026-10-25. Робоча специфікація для погодженого напряму «Футбол наших громад».
Tablet/mobile та аркуш станів погоджені власником. Погодження дизайну не
скасовує наведені нижче обмеження перевірок і борг desktop-типографіки.
Це дизайн макетів, не реалізація маршрутів, API, меню чи інтерактивних компонентів.
Основа: [бриф](proleague-homepage-design-brief.md),
[артдирекція](proleague-homepage-art-direction.md),
[демодані](proleague-homepage-demo.json).

## Адаптивна композиція

Контрольні CSS-ширини для наступної реалізації: 320/390, 834 та 1440 px.
Розміри screenshot-файлів Stitch не є доказом цих viewport-розмірів.
Межі переходів попередні: mobile <768, tablet 768–1199, desktop ≥1200 px;
їх потрібно перевірити за фактичним вмістом, zoom і довгими назвами.

| Блок              | Mobile                                 | Tablet                                      | Desktop                            |
| ----------------- | -------------------------------------- | ------------------------------------------- | ---------------------------------- |
| Header            | Логотип + «Меню»                       | Логотип + «Меню»                            | П’ять навігаційних посилань        |
| Hero              | Компактний, дії одна під одною         | Дві дії поруч, якщо поміщаються             | Фото й виразний заголовок          |
| Матчі             | Одна колонка, повні назви              | Дві колонки за достатньої ширини            | Дві картки поруч                   |
| Матеріали/таблиця | Головна історія → таблиця → дві новини | Історія → широка таблиця → дві новини поруч | Редакційна колонка + таблиця збоку |
| Змагання          | Одна колонка                           | Дві колонки, третя картка наступним рядком  | Три колонки                        |
| Контакти/footer   | Вертикально                            | Перенесення блоків за шириною               | Розгорнуте компонування            |

Фото зберігає змістовний focal point; не стискати desktop як картинку.
Назви команд і змагань переносяться без ellipsis. Горизонтальне прокручування
дозволене всередині таблиці, не всієї сторінки. Зберігати всі показники та
видимий підпис «Перегортайте таблицю горизонтально» там, де є overflow.
Для реалізації — семантична таблиця, caption із контекстом і доступний
scroll-region із видимим фокусом. Не ховати стовпці без доступу до повної інформації.

Основний текст 16–18 px, підписи від 14 px; touch targets цільово ≥44×44 px.
Не додавати нижню app-панель, глобальний сезон, пошук, профіль або підписки.

## Контракти станів компонентів

| Компонент/стан           | Видимий зміст                                                                        | Дія та правило                                                  |
| ------------------------ | ------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| Матчі: initial loading   | Skeleton + «Завантажуємо матчі…»                                                     | aria-busy на блоці, не фіктивний рахунок                        |
| Матчі: error             | «Не вдалося завантажити матчі. Спробуйте ще раз.»                                    | «Спробувати ще раз»; решта сторінки доступна                    |
| Матчі: empty             | «У цьому змаганні поки немає опублікованих матчів.»                                  | Фільтр доступний, без нескінченного spinner                     |
| Retry: pending           | «Завантаження…»                                                                      | Захист від повторного запиту цієї дії, без блокування всього UI |
| Таблиця: empty           | «Таблиця стане доступною після публікації відповідного етапу.»                       | Не малювати нульову таблицю                                     |
| Кубок: not applicable    | «Для цього етапу кубка турнірна таблиця не застосовується. Перегляньте матчі кубка.» | Перехід до матчів; це не error                                  |
| Таблиця: partial failure | «Таблицю тимчасово не вдалося оновити. Інші розділи доступні.»                       | Локальний retry; не приховувати новини й матчі                  |
| Фото: unavailable        | Нейтральний placeholder зі збереженим aspect ratio                                   | Заголовок і посилання статті залишаються доступними             |

Під час оновлення наявні дані можна зберегти лише якщо вони справді є;
позначати їхній реальний timestamp та стан оновлення, не вигадувати свіжість.
Зміна фільтра не повинна видавати старі матчі за результати нового фільтра.
Порожня стрічка новин/каталог змагань — спокійне пояснення без фіктивних карток;
локальна помилка їх завантаження — локальний retry, за тим самим правилом.

## Статуси матчів

- Заплановано: відомі дата/час або явне «Час уточнюється»; без рахунку.
- Завершено: лише підтверджений результат; статус поруч із рахунком.
- Перенесено: «Нові дата й час уточнюються», якщо їх ще не підтверджено.
- Скасовано: без присудженого рахунку чи переможця.
- Значення статусу передається текстом, не лише кольором.

Повний стан результатів використовує m1–m6, найближчі — лише m7–m8.
m9/m10 не потрапляють у список найближчих як заплановані.

## Навігація та керування

Закрите меню: кнопка «Меню», aria-expanded=false, aria-controls.
Відкрите: підпис «Навігація», кнопка «Закрити», ті самі п’ять посилань.
Якщо панель модальна: focus trap, inert для фону, Escape закриває,
закриття повертає фокус до тригера. На переході до desktop прибрати modal state.
Без JS у кінцевій реалізації потрібна доступна базова навігація.

Для кнопок визначити default/hover/focus-visible/active/disabled/pending.
Disabled має зрозумілу причину, не є заміною empty/error.
Вкладки — узгоджена tab-семантика, selected state та клавіатурні стрілки;
пов’язана панель і фільтр мають доступні назви. Не змішувати tab і звичайні
посилання без потреби. Поважати prefers-reduced-motion, без обов’язкової анімації.

## Перевірки перед реалізацією

1. Погодити tablet/mobile та аркуш станів за screenshot і фактичним HTML.
2. Перевірити 320/390/834/1440 CSS px, zoom 200%, перенесення довгих назв.
3. Перевірити відсутність page overflow; окремо — scroll таблиці та фокус.
4. Звірити демоконтент, дати, показники й відсутність вигаданих venue/правил.
5. У реалізації перевірити меню, retry, tabs, клавіатуру й screen reader.
6. Окремо виконати перевірку контрасту й доступності на реальних компонентах.

Статичний макет не підтверджує роботу пунктів 2–6 та відповідність WCAG.

- Tablet: `e1006b88a5b9480f808b61ff10e06610`.
- Аркуш станів: `bad6bdfa93d24ff993440658be735d98`.

Експорти локально: `.stitch/designs/homepage-mobile.png/html`,
`homepage-tablet.png/html`, `homepage-states.png/html`; у Git вони ігноруються.
Metadata й запити — `.stitch/homepage/`, звіт — `render-checks.json`.

Через playwright-cli перевірено локальний HTML у Chromium на CSS-ширинах
320/390/834/1440. На mobile/tablet відсутнє переповнення сторінки,
таблиця має локальний scroll, п’ять фото завантажилися, дві заплановані
зустрічі й усі чотири рядки таблиці відповідають демонабору.
Серед видимих p/button/a/td/th mobile/tablet немає кегля меншого за 14 px;
це вибіркова перевірка, не повний аудит типографіки. Кнопка меню має висоту
44 px на mobile і 46 px на tablet. Аркуш станів звірено зі screenshot/HTML.

Під час уточнень виправлено регресії генератора: дубль змагань, втрату таблиці,
сторонню навігацію та вигадане правило кваліфікації. Поточні metadata ведуть
до виправлених екранів; проміжні експорти не додаються до Git.

Відомий борг: у незміненому desktop 57 видимих p/button/a/td/th мають кегль
менше 14 px при ширині 1440 px. Погодження композиції не означає прийняття
цієї типографіки; її потрібно вирівняти перед кінцевим handoff.
Zoom 200%, landscape, screen reader, контраст і фактичні інтеракції ще не
перевірено. Твердження провайдера «всі вимоги доступності дотримано» не прийняте
як доказ. Пропозиції створити сторінку матчу, повну таблицю, пошук новин або
нову кубкову сітку не виконували: вони поза поточним scope.
